# Building in CLion

`CMakeLists.txt` starts with:

```cmake
include($ENV{IDF_PATH}/tools/cmake/project.cmake)
```

Without `IDF_PATH` that reads `include(/tools/cmake/project.cmake)`, CMake
aborts before defining a target, and CLion reports "this file does not belong
to any project" for everything under `main/`. If it configures but you still
get `Cannot resolve symbol 'uint8_t'`, CLion is configuring with its default
toolchain instead of the Xtensa one, so none of the target's standard headers
are on the include path.

Both are fixed by a local ESP-IDF plus the checked-in CMake preset.

## 1. Install ESP-IDF v6.1.1

Use `C:\Espressif\frameworks\esp-idf-v6.1.1`, with the tools under
`%USERPROFILE%\.espressif`. Keep earlier SDK installations for rollback:

```powershell
git clone -b v6.1.1 --depth 1 --recursive --shallow-submodules `
    https://github.com/espressif/esp-idf.git C:\Espressif\frameworks\esp-idf-v6.1.1
cd C:\Espressif\frameworks\esp-idf-v6.1.1
.\install.ps1 esp32s3
```

Run that from PowerShell, not Git Bash. `idf_tools.py` detects MSYS and refuses
with "MSys/Mingw is not supported".

The manifest pins v6.1.1 to match the Docker image and CI. ESP-IDF 6 uses
Mbed TLS 4 and PSA Crypto; this firmware's DTLS and EC-JPAKE configuration
must be built with the matching SDK.

## 2. Environment

Activate the selected SDK before starting CLion. If persistent user variables
still point to the previous SDK, launch CLion from the activated shell without
changing global user variables. The build wrapper automatically selects the
standard v6.1.1 installation; pass `-IdfPath` if it is installed elsewhere. It
restores the caller's process environment on exit.

If you ever need to redo it, source the export script and copy what it sets:

```powershell
$env:IDF_PATH = 'C:\Espressif\frameworks\esp-idf-v6.1.1'
Remove-Item Env:\IDF_PYTHON_ENV_PATH -ErrorAction SilentlyContinue
. C:\Espressif\frameworks\esp-idf-v6.1.1\export.ps1
```

Environment changes only reach newly started processes, so restart CLion (fully,
not just the project) after any change here.

## 3. Open the project

The repo ships `CMakePresets.json` with an **esp32s3** preset that mirrors what
`idf.py` configures: Ninja, `build/idf6/` as the binary directory, `IDF_TARGET`, and
ESP-IDF's `toolchain-esp32s3.cmake`. CLion picks presets up automatically.

Open the project, choose the **ESP32-S3 (ESP-IDF 6.1.1)** profile, and let it reload.
Because the preset points at the same `build/idf6/` the wrapper uses, CLion and `idf.py`
share one cache instead of fighting over two.

The SDK-specific directory preserves earlier `build/` artifacts. If the selected
directory contains a cache generated by another SDK or a container, use another
build directory or retain those artifacts before cleaning it. A container cache
records its own `CMAKE_HOME_DIRECTORY` and CLion cannot reuse it.

## 4. Build and flash

Build the `app` target, or from a terminal:

```
idf.py -B build/idf6 -p COM5 app-flash monitor
```

`build-native.ps1` wraps the same thing with ccache switched on and an
app-only flash by default, so an edit-compile-flash cycle is a few seconds and
never touches the saved Wi-Fi, Thread or Matter data:

```
.\build-native.ps1 -Port COM5
```

Note that editing `sdkconfig.defaults` does not update an existing `sdkconfig`.
Change both, or back up and remove `sdkconfig` before rebuilding to regenerate
it from defaults. `-Clean` clears `build/idf6/` but retains `sdkconfig`. Use
`-BuildDir` to select another directory; keep SDK versions in separate caches.

Serial is 115200. Some terminals assert DTR/RTS and reset the board when opening
the port. `tools/robust_cmd.py` leaves both inactive for read-only diagnostics
that preserve uptime.

## The Docker build still works

`build.ps1` is what CI uses and stays reproducible regardless of what is
installed locally. It compiles inside a Docker volume and drops the flashable
artifacts in `dist/`, so it never writes into `build/` and won't fight CLion's
CMake cache.

```
.\build.ps1 -Port COM5
```
